## 本周最常见的技术关键词是什么？它们如何变化？

I’m watching **agentic engineering** take over from vibe coding as the everyday term. It describes developers applying engineering control, auditing, and reproducibility to the outputs of AI coding agents—replacing the old habit of blind trial and error.

I noticed the search interest in **system prompt leaks** cooling off, yet the audit repository `asgeirtj/system_prompts_leaks` surged significantly this week. Security researchers keep demanding that vendors prove system prompts haven’t been leaked and contain no steganographic markers, and they’re actively extracting the system instructions of models like Claude to test the boundaries.

This week **memory security** showed up in a concentrated way, pointing to long-term memories stored without protection in AI assistants—retrievable via prompt injection to extract users’ full names, employers, and answers to security questions. I see users starting to demand provable memory isolation.

Security practitioners temporarily named **GitLost** to describe an attack path where prompts are injected into a public Issue to trick AI agents into leaking private repository information. The name spread fast, then its search heat hit zero, leaving behind a labelled attack pattern.

The concept of **codebase memory** kept rising with the project `DeusData/codebase-memory-mcp`. It reflects developers’ expectation that AI coding agents maintain a semantic knowledge graph of an entire codebase across sessions—not just index the current file.

To me, the way these terms become everyday vocabulary signals a rewrite: developers and security practitioners are turning agent behavior from “trial-and-error output” into an engineering entity that demands audit. They want provable isolation at every layer—system prompts, assistant memory, codebase access—against leaks, injections, and irreproducibility. The nightmare scenario I keep hearing from teams centers on the unobservable cost of agents, private data being silently uploaded, and a trust vacuum behind automation with zero audit evidence.

**AI coding assistants’ “memory betrayal”**

**My judgment:** A coding assistant with a leaky memory is a walking privacy incident. When the fix is “run it in a sterile VM,” the assistant has become a threat to be sandboxed, not a partner to be invited in.  
**Counter view:** The vision was a seamless, context‑aware aide that speeds up your work; the reality is a tool that can spill your secrets and forces you to spend time on defensive infrastructure that never existed before.

**AI agent tools’ “permission paradox”**  
AI keyboards, coding agents (Acti, Harness IDE, and the like) are expected to simplify operations through deep system integration. Yet growing fears over memory leaks and permission abuse—right on the heels of the previous stories—make granting high privileges a hard sell. At the same time, the paid models of most similar products remain unproven, creating a stark disconnect between the promised productivity leap and any real commercial loop.  
**My judgment:** These tools demand root access to your digital life in order to be useful, but every fresh leak report shrinks the pool of people willing to grant it. Without trust, deep integration is a non‑starter, and without deep integration, the product’s value proposition collapses.  
**Counter view:** The sales pitch is “just let the agent handle everything” for maximum efficiency, but the market is responding with a rational “show me the security proof and a real business case first”—and neither is being delivered.

These gaps together point to one fact I keep running into: today’s tech‑product narratives put a spotlight on capability breakthroughs and efficiency gains, but cross‑signal evidence keeps revealing the same systems under‑deliver on security, reliability, evaluation transparency, and user control. Every one of those deficits eats away at the core value the tools themselves claim to deliver.
