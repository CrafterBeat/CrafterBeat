Instead, agent capabilities are being baked directly into existing interfaces like the keyboard and inbox, letting agents tackle background tasks without yanking the user out of context. This is driving a real need to describe “non-chat agent interfaces.”

- **Evaluating agents** is becoming a distinct demand, separate from the old habit of just benchmarking models. With tools like AgentX entering the pipeline, failures like inconsistent agent outputs and uncontrollable behavior are no longer hidden—they’re surfaced as dedicated evaluation, debugging, and auditing requirements.

- **Declarative skill filesystem** is hardening from community coinage into a structured way to define agent capabilities, pushed by projects like taste-skill and stop-slop. I’m seeing developers replace prompt engineering with auditable file structures that demand traceable, reproducible agent behavior, and they’re weaving the cleanup of low-quality AI “slop” directly into skill file management.

- **Cybersecurity skills for AI agents** are spreading fast among security pros. Penetration testing and MITRE ATT&CK mappings are getting packaged into deliverable agent skill files. At the same time, the agent itself is being treated as a potential attack surface, pushing “security skills” to evolve from human playbooks into executable, auditable, structured definitions.

Taken together, these terms tell me developers, users, and security teams are recasting their trust problem with AI agents using a new vocabulary: transparent marks, evaluable outputs, skill files, audit interfaces. It’s all being translated into verifiable demands for tool behavior visibility, operational traceability, and supply-dependency risk. What really scares them, I think, is the shadow burden of unauditable agent behavior, vendors tracking usage opaquely, failed automation expectations that silently eat supervision time, and an inability to self-prove business continuity when model access breaks.
