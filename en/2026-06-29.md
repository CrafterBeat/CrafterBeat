## 如果今天有 2 小时或一个完整周末，应该做什么？

Today, two independent signals on HN point to the same opportunity: replacing random LLM outputs with deterministic evaluation. GLM 5.2 beats Claude Code on IDOR detection with a 39% F1 score versus 32% ([@jms703](https://news.ycombinator.com/item?id=48709670), 1056pts), revealing open-source models’ ability to outperform closed-source services on vertical benchmarks, at a cost of just $0.17 per vulnerability. In another post, HackerRank’s open-source ATS tool [hiring-agent](https://github.com/interviewstreet/hiring-agent) gave the same resume scores of 90, 74, 88, and 83 across three runs ([@sambellll](https://news.ycombinator.com/item?id=48713832), 938pts). The comment by [@some_random](https://news.ycombinator.com/item?id=48723473) hits the nail on the head: "This complete lack of reproducibility is what happens when you throw LLMs at a complicate problem without sufficient shaping, workflows, etc." Meanwhile, another 845-point post on the HN front page shows Google helping Pollen remove negative coverage about its CEO ([@taubek](https://news.ycombinator.com/item?id=48716902)), and [@A_D_E_P_T](https://news.ycombinator.com/item?id=48717100) points out that the entire "reputation management" industry is covering up the truth through SEO and removal requests — there's budget in this market, but the means are ethically ambiguous.

The logic when merging these three signals is clear: (1) LLM randomness makes single scores untrustworthy, yet the community already accepts the idea of using LLMs for evaluation; (2) businesses have budgets to manage their "scores," whether hiring scores or reputation scores; (3) open-source models can match or even surpass closed-source services on specific tasks, at near-zero cost.

**Why now**: HackerRank's ATS hitting 938pts on HN means there's massive distribution leverage today. A product that forks this tool and fixes the "randomness" issue can cold-start directly under the same post. The time window is about 24–48 hours.

**What to build**: a **pseudo-quantitative resume evaluation tool**. The core difference is not scoring directly with an LLM, but parsing the resume into structured fields, applying multiple deterministic rule checks to each field (skill keyword matching, experience years calculation, education background verification), and then outputting a score via a simple weighted formula. LLMs are used only for structuring and extraction, not for judgment. This solves the reproducibility issue pointed out by @some_random, while keeping the workflow appearance of HackerRank’s ATS.

**Tech stack**: Use the `Anthropic Messages API` or `GLM 5.2 API` (via zhipuai) for resume JSON extraction, then use Python + Streamlit on the frontend for the rule engine that shows the scoring process. "The first step is calling the `/v1/messages` endpoint with `requests`, passing in `prompt='Extract structured fields from this resume: name, skills, years_of_experience, education'`, then feeding the extracted JSON into the rule engine—and the rule engine is just 50 lines of if-else."

**Why not the other candidates**:
- **own.page** (PH 688 upvotes) is a personal website generator—a social media tool—irrelevant to the "actionable opportunity" and in an oversaturated market.
- **Mailwarm 2.0** (PH 700 upvotes) is an email warm-up tool requiring email infrastructure and delivery domain knowledge; you can’t build a usable MVP in two hours.
- **GLM 5.2 security scanning tool**: Simply wrapping GLM 5.2 for code security scans would compete with semgrep.dev’s existing product, and that team has already published their benchmark and methodology—they could offer native support at any time.

**Key judgment**: The product that can be built in two hours today is **fork HackerRank ATS, inject a deterministic rule engine to replace LLM scoring**. Tech stack: Anthropic Messages API (extraction) + Python rule engine + Streamlit (UI). Pricing: free and open source; the first version gets users through exposure on the HN front-page post. Distribution strategy: comment under the original HN post, "Here's a fork that produces the same score every time," with the GitHub link.

**Counter view**: HackerRank’s ATS is itself an open-source project. If their team sees the HN feedback and fixes the problem themselves in 1–3 days (by adding result caching or rule constraints), the fork’s value quickly goes to zero. I see this not as a moat but a two-day cash flow opportunity. Historical precedent: Every year, 5–10 "open-source ATS" projects go viral on HN once and then fade, because the paying buyers in the recruiting market are on LinkedIn, not GitHub.

Today’s evidence across chapters converges on a single uncomfortable shift. - **ollama**: the official Python client for Ollama, acting as the interface to interact with local large language models in the AI toolchain, typically used to build AI agents or developer assistance tools based on local models.
- **serde**: a serialization/deserialization framework in the Rust ecosystem, responsible for converting data structures to common data formats, typically underpinning the data conversion layer in web services, config parsing, and API communication.
- **gradio**: a Python library for quickly creating interactive interfaces for machine learning models, providing instant UI for model validation and internal demos, typically used to build prototypes and showcase model performance within teams.
- **tokio**: an async I/O runtime for Rust, providing an event-driven non-blocking concurrency model for applications, typically serving as the foundational execution environment for network services, proxies, and database drivers.
- **tauri**: a framework for building lightweight desktop applications using web front-end technologies, replacing Electron with a smaller footprint in desktop tool development, typically used to build local developer tools and cross-platform clients.
